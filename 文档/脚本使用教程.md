## 一、路由器上的脚本

全部在 `/etc/campus_network/` 下。仓库里的源文件在 `一键配置脚本/`。

| 脚本 | 版本 | 谁在调它 | 干什么 |
|---|---|---|---|
| `auto_login.sh` | v3.0 | cron 每 5 分钟 / 手动 / 守护进程 | 执行三步认证 |
| `fast_recovery_daemon.sh` | v2.2 | `/etc/init.d/fast_recovery` | 每秒检查，分级恢复 |
| `boot_auth.sh` | — | `/etc/init.d/campus_auth` | 开机等网络就绪再认证 |
| `route_watchdog.sh` | — | campus_auth 的 boot() | 开机早期加速 STA 重连 |
| `dns_fix.sh` | v2.2 | 手动 | 四层 DNS 修复 |

### auto_login.sh

```bash
/etc/campus_network/auto_login.sh            # 正常执行（先检查网络再认证）
/etc/campus_network/auto_login.sh --force    # 跳过预检，强制走完整三步
```

**什么时候用 `--force`**：ping 得通但网页弹登录页（会话过期）。这时预检会认为
"网络正常"而跳过认证，必须 `--force`。

**改账号密码**：文件开头四个变量

```sh
USERNAME="学号"
PASSWORD="密码"
OPERATOR_SUFFIX="@henuyd"
CAMPUS_CODE="07cdfd23373b17c6b337251c22b7ea57"
```

**验证成功**：`tail -20 /tmp/campus_network.log`，第三步响应里出现
`"message":"认证成功"`。**只看第三步**——前两步的 check-only 校验很宽松，
成功了也不代表能上网。

### fast_recovery_daemon.sh

```bash
ps | grep [f]ast_recovery                # 在不在跑
/etc/init.d/fast_recovery restart        # 重启
/etc/init.d/fast_recovery stop           # 停
grep FastRecovery /tmp/campus_network.log | tail -30   # 看它做了什么
```

**分级恢复逻辑**：

| 级别 | 判据 | 动作 |
|---|---|---|
| 正常 | 有路由、STA 连着、HTTP 没被劫持 | 什么都不做 |
| 2 | STA 连着但默认路由丢了 | DHCP 续租 |
| 3 | 持续 15 秒没恢复 | 先续租（比重启温和） |
| 4 | STA 掉了或路由一直没回来 | `ubus call network.interface.wwan down/up` |
| 5 | 恢复后 HTTP 被劫持 | 触发 `auto_login.sh` |

**认证退避**：最小间隔 300 秒，连续失败 3 次后拉长到 1800 秒。避免撞学校限流。

> ⚠️ 脚本里**不用 `wifi reload`**。满流量时这个命令会触发 mtk_eth 驱动崩溃，
> 整机重启（2026-10-24 在 pstore 里抓到栈）。只用 `ubus` 操作 wwan 单接口。

### boot_auth.sh

```bash
grep BootAuth /tmp/campus_network.log    # 看开机认证走没走
```

最长等 10 分钟网络就绪再认证。由 `/etc/init.d/campus_auth`（`START=99`）后台拉起。

> 这个 init 脚本有两个必须保留的写法，改动前先读文件头的注释：
> ① `boot()` 里必须调 `start`；② 不要用 `procd_set_param command /bin/sh -c` 跑多行脚本。

### dns_fix.sh

```bash
sh /etc/campus_network/dns_fix.sh
nslookup zwyy.henu.edu.cn      # 修复后应返回 202.196.96.29
```

四层修复：hosts 写死 → UCI 域名分流 → rebind 豁免 → 过滤 IPv6。
细节见 [原理详解.md](原理详解.md) 第六节。

## 二、电脑上的部署脚本

### !FIX.bat + fix_remote.sh（给别人排障用）

**用途**：路由器上不了网，让对方自己跑一下，自动诊断 + 修复。

```bash
# 两个文件放在同一个文件夹，双击 !FIX.bat
# 输入路由器 IP（默认 192.168.1.1）和后台密码
```

它会：

1. 找到 `mode='sta'` 的无线接口（自动识别，不写死配置名）
2. 检查这个接口有没有被误设 SSID / 加密方式 / 密码
3. 有错就改（这是"改了 WiFi 密码后上不了网"的根因）
4. 重连 wwan，验证 IP、默认路由、外网
5. 不通就强制认证一次
6. 还不行，把诊断信息（日志、信号、CAKE 队列）全部打印出来

**最容易踩的错**：把宿舍热点的密码改到了 `henu-student` 那个 STA 接口上。
脚本会自动找出来并清掉。

`fix_remote.sh` 是真正在路由器上跑的脚本，通过 `ssh root@IP "cat > /tmp/... && sh ..."` 送过去，
不需要手动上传，也不需要 `scp`。

### deploy.py + !START.bat

```bash
cd 一键配置脚本
python deploy.py              # 交互式菜单
python deploy.py lazy         # 懒人模式，只需填密码
python deploy.py wifi         # 快速切换校园网
```

Windows 下直接双击 `!START.bat`。

### auto_config.sh

路由器上跑的一键配置脚本，`deploy.py` 会自动上传并执行它。手动用法：

```bash
scp 一键配置脚本/auto_config.sh root@192.168.1.1:/tmp/
ssh root@192.168.1.1 "sh /tmp/auto_config.sh"
```

七步：环境检查 → root 密码 → 宿舍 WiFi → 无线 WAN → 认证脚本 → 定时重连 → CAKE 流控。

> 这个文件里内嵌了几份脚本副本，可能滞后于同目录的独立文件。
> **权威版本是 `auto_login.sh.template` / `fast_recovery_daemon.sh` / `dns_fix.sh` 等独立文件。**

### auto_login.sh.template

认证脚本模板，占位符 `__USERNAME__` / `__PASSWORD__` / `__OPERATOR_SUFFIX__`。
真实密码不进仓库。校编码是硬编码的默认值（不是凭据，见 [原理详解.md](原理详解.md) 第二节）。

### crontab.root

crontab 模板：

```
*/5 * * * * /etc/campus_network/auto_login.sh
0 4 * * 1,4 /sbin/reboot
```

> ⚠️ 严禁 `@reboot` / `@daily`。busybox crond 不支持，写进去会崩溃并进入重启循环，
> 连 `*/5` 一起失效。开机任务交给 `/etc/init.d/`。

## 三、监控工具

### probe_stall.sh（路由器上，自动跑）

每分钟测 4 个视频/图片站点，首字节超过 2 秒或失败就记一份现场快照。

```bash
tail -50 /overlay/probe.log
```

带 `卡顿:` 的行 = 那一刻确实慢，同一行里有当时的 WiFi 速率、CAKE 计数、RTT。
正常时每 30 分钟留一行心跳。日志超 300KB 自动截断到后 1000 行。

**部署**：

```bash
ssh ax3000t "cat > /root/probe_stall.sh" < 监控工具/probe_stall.sh
# crontab 加一行
* * * * * /root/probe_stall.sh >/dev/null 2>&1
```

### monitor.py（电脑上，手动跑）

从**电脑**测网络延迟。双击 `监控工具/!MONITOR.bat` 或：

```bash
cd 监控工具
python monitor.py live        # 实时监控，9 个站点，0.5 秒刷新
python monitor.py stress      # 压力测试，9 站点 × 30 轮
python monitor.py compare     # 对比两次测试结果
```

需要 Python 3.8+，不需要装第三方包。结果自动存 `test_results/`。

**什么时候用哪个**：

| 工具 | 视角 | 适合 |
|---|---|---|
| `probe_stall.sh` | 路由器视角 | 事情已经发生，要事后查证据 |
| `monitor.py live` | 电脑视角 | 正在出问题，实时看哪一跳慢 |
| `monitor.py stress` | 电脑视角 | 想知道基线质量，和以前对比 |
